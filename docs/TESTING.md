# 测试与兼容反馈

## 自动检查范围

1. JVM：结算判断需要组合信号，排除非目标 App、退款 / 历史订单 / 支付结果；金额不静默舍入；临时放行与限频；分享解析。
2. Android UI：未开启无障碍时，新增商品、展示价格并记录放弃。
3. 模拟器服务链路：只在 debug APK 中的本机模拟页面开启测试服务，验证提醒覆盖面板和继续后 15 分钟放行；结束后恢复服务设置。
4. 检查安装包不获得互联网权限、不启用应用备份。

模拟页面没有真实商家、账号、订单、付款或网络请求。`FixtureActivity` 不包含在 release APK 中，debug 路径不代表真实购物平台已经兼容。模拟器截图请标注模拟环境。

## 真机验证顺序

先验证基础清单，再入口提醒，最后自行决定是否试验结算提醒。不需要为了验证功能完成真实付款。

| 场景 | 观察重点 |
| --- | --- |
| 拒绝无障碍与通知 | 清单仍可新增、保存、重开读取、删除 |
| 单 App 入口模式 | 进入提醒；切换到其他 App 及时撤下；不读取页面文字 |
| 继续购物 | 面板关闭，15 分钟内不重复；结束临时放行可恢复 |
| 暂停 / 关闭模式 | 不再提取页面内容，撤下现有提醒 |
| 结算模式 | 只观察进入结算页是否提醒，不执行付款来“试拦截” |
| 查订单、退款、历史记录 | 不应当按准备下单处理；有误判可关闭实验模式 |
| 外部支付 App、系统设置、锁屏 | 不应残留覆盖面板 |
| 重启、省电、切换账号 / 工作资料 | 记录服务状态，不预先假定恢复成功 |
| 大字体、横屏、小屏幕 | 确保提醒按钮可以滚动访问与关闭 |
| 关闭到期通知 | 取消后续任务；系统通知页也应允许关闭 |
| 删除全部数据 | 清单为空，模式和同意状态复位，提醒任务取消 |

报告中注明手机、系统、Android 版本、缓购版本、购物 App 版本、语言、字体大小、模式和步骤。不要上传个人与支付信息。
